# MuWorld 추가/수정 요구사항

이 문서는 미완료 구현과 아직 확인하지 못한 검증 항목만 관리합니다. 해결된 요구사항은 삭제하며, 일부 검증만 남은 기능은 그 검증만 기록합니다. 기존 항목 번호는 추적을 위해 유지합니다.

기능 사용법은 [ReadMe.md](../ReadMe.md), 내부 구조는 [Tech.md](Tech.md), 검증 절차와 결과는 [quality-validation.md](../front%20interface/docs/quality-validation.md)를 참고합니다.

## 운영 원칙

- 구현과 검증을 구분하며, 확인하지 않은 동작은 완료로 기록하지 않는다.
- 자동 테스트만으로 실제 플레이 감각이나 실기기 접근성을 검증했다고 판단하지 않는다.
- 해결된 요구사항은 이 백로그에서 제거하고 필요한 사용법과 구조 설명을 해당 문서에 반영한다.
- 일부만 해결된 항목은 남은 작업과 완료 조건만 유지한다.

## P0: 오디오와 실제 플레이 검증

### 2. 오디오 장치·포맷별 안정성 검증

남은 작업:

- 동일한 실제 음악의 WAV와 비-WAV 버전을 각각 5회 이상 재생하고 audio clock summary의 jitter, drift, 역행, stall과 timing bias를 비교한다.
- 실제 장치에서 pause/resume 후 첫 2초 판정, preview 전환, 곡 종료 시 위치 이상과 소리 끊김을 확인한다.
- 대체 오디오 엔진과 비교 실험하고 측정 결과로 교체 필요성을 판단한다.

완료 조건:

- 포맷·장치별 측정 결과와 청취 결과를 남기고, 반복 재생이나 재개 시 비정상적인 timing drift가 없음을 확인한다.

### 3. 사람 입력으로 플레이 감각 검증

남은 작업:

- 고정 기준 차트와 실제 음악을 사용해 튜토리얼·중간 난이도·고밀도 구간을 직접 플레이한다.
- chord, Long, Slide, BPM 변화, rest 구간에서 판정선, note speed, hit sound, feedback과 결과 화면을 체크리스트로 확인한다.

완료 조건:

- 각 난이도의 사람 입력 검증 결과를 영상 또는 로그와 함께 남기고, 곡 시작부터 결과 화면까지의 문제를 해결한다.

### 4. 메뉴 이동과 화면 요소 실기기 검증

남은 작업:

- 실제 screen reader에서 메뉴의 시각 순서, 이름, 설명과 실행 동작을 확인한다.
- Play, Settings, Player Stats, Restart, Quit까지 키보드로 이동하고 실행한다.
- 1366x768, 1920x1080, 2560x1080에서 Settings, Player Stats, Quit의 label과 hit target을 자동 검사하고 DPI·글자 확대 상태도 확인한다.

완료 조건:

- 접근성 노드와 화면 요소가 일치하고, 텍스트·클릭 영역 겹침이나 접근 불가능한 메뉴가 없다.

## P1: 제작·탐색 흐름과 사용성

### 5. 신규 사용자 튜토리얼 검증

남은 작업:

- 신규 사용자가 README 없이 키 배치, Tap/Long/Slide, Early/Late를 이해하고 첫 곡을 끝낼 수 있는지 관찰한다.
- 재연습·건너뛰기·보정·곡 선택 흐름을 직접 확인하고, 연습과 본게임의 판정 체감이 일치하는지 검증한다.

완료 조건:

- 관찰 결과를 기록하고 첫 플레이를 막거나 오해를 유발하는 안내를 보완한다.

### 7. 차트 에디터 남은 기능과 제작 검증

남은 작업:

- tempo event를 추가·수정하는 UI를 구현하고 입력 검증과 저장·재열기 테스트를 추가한다.
- 에디터에서 1분짜리 차트를 직접 제작한 뒤 저장·재열기·Song Select 진입·실제 플레이까지 확인한다.
- DPI와 글자 크기를 바꾸어 도구, 경고 이동, 노트 편집을 사용할 수 있는지 확인한다.

완료 조건:

- BPM 변화가 있는 차트를 UI에서 편집할 수 있고, 제작한 차트가 저장 후 플레이에 정확히 반영된다.
- 지원 화면 배율에서 편집 조작이 가려지거나 접근 불가능하지 않다.

### 8. 곡 라이브러리 초기 로딩과 실패 상태 개선

남은 작업:

- 초기 파일 탐색과 최초 난이도 조회를 비동기로 처리해 UI 정지를 방지한다.
- 곡별 분석 실패 사유를 영속 상태로 관리하고 목록에서 확인·재시도할 수 있게 한다.
- 실제 곡 100개 이상으로 초기 로딩, 필터·정렬·목록 이동의 응답 시간을 측정한다.
- 손상 파일과 누락된 리소스를 섞어 다른 곡의 탐색·재생에 영향을 주지 않는지 확인한다.

완료 조건:

- 초기 로딩 중에도 UI가 응답하고, 실패한 곡의 원인을 확인한 뒤 재시도할 수 있다.
- 100곡 이상에서 측정한 탐색 성능과 오류 격리 결과를 기록한다.

### 9. 사용자 곡 리플레이 전체 흐름 검증

남은 작업:

- 사용자 WAV·비-WAV 곡의 동일한 v3 replay를 실제 UI에서 각각 5회 이상 반복 재생한다.
- 장치별로 score, 판정 분포, 최대 콤보뿐 아니라 실제 게이지·등급·클리어 결과까지 비교한다.

완료 조건:

- 전체 게임 흐름에서 반복 결과가 일치한다. 기준 결과의 등급·클리어 값을 주입하는 harness 결과만으로 완료 처리하지 않는다.

## P2: 리소스·성능·접근성 검증

### 10. 손상된 스킨·BGA 조합 검증

남은 작업:

- 손상 이미지, 잘못된 manifest, 누락 파일, 크기 제한 초과 리소스의 조합을 실제 실행으로 확인한다.
- 스킨과 곡을 반복 전환하며 대체 표시와 리소스 해제가 정상 동작하는지 확인한다.

완료 조건:

- 잘못된 리소스가 있어도 게임이 계속 실행되고, 반복 전환으로 메모리·GDI 객체가 지속 증가하지 않는다.

### 11. 최종 빌드의 장시간 실플레이 성능 검증

남은 작업:

- 최종 빌드에서 실제 오디오와 화면 전환을 포함해 10분 이상 플레이하고 frame time, allocation, 메모리, GDI 객체를 측정한다.
- 목표 장치에서 저사양·high quality 모드의 시각 효과와 성능 차이를 기록하고 회귀 예산을 검증한다.

완료 조건:

- 최종 빌드의 실플레이 측정 결과가 남고 메모리·GDI 객체가 지속 증가하지 않는다.
- 중간 빌드의 렌더링 전용 soak 결과와 최종 실플레이 결과를 구분한다.

### 12. 전 화면 접근성 검증과 누락 보완

남은 작업:

- Main, Song Select, Settings, Statistics, Analyze, Chart Editor를 키보드만으로 사용하며 누락된 accessible node와 잘못된 focus order를 보완한다.
- 실제 screen reader의 이름·설명·실행 결과가 화면과 일치하는지 확인한다.
- 고대비, 색각 보정, reduced motion, text size가 모든 주요 화면에 적용되는지 확인하고 누락을 보완한다.

완료 조건:

- 주요 흐름을 키보드와 screen reader로 사용할 수 있고, 접근성 설정을 켜도 정보나 조작을 잃지 않는다.

## 검증 게이트

새 기능이나 수정은 최소한 다음 검증을 통과해야 한다.

```powershell
& ".\front interface\dotnet\dotnet.exe" build ".\front interface\Tests\MuWorld.SelfTests.csproj" -c Debug --no-restore -v:minimal
& ".\front interface\dotnet\dotnet.exe" ".\front interface\Tests\bin\Debug\net9.0-windows\MuWorld.SelfTests.dll"
```

Release 검증은 `game start.exe`가 실행 중이면 파일 잠금으로 실패할 수 있다. Release 검증 전에는 실행 중인 Release 앱을 종료한다.

완료 기준:

- 빌드 경고 0개
- self-test 실패 0개
- 변경한 UI를 최소 1366x768과 1920x1080에서 직접 확인
- 새 저장 데이터가 기존 저장 파일을 깨지 않음
- 문서가 실제 코드와 불일치하지 않음
