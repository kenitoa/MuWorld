# MuWorld 구현 명세

이 문서는 현재 소스에 구현한 동작과 기획에서 아직 완료하지 않은 항목을 구분합니다. 물리 하드웨어 정확도나 측정하지 않은 성능을 보장하는 사양서는 아닙니다.

1. **실행 구조는 오프라인 Electron 데스크톱 앱입니다.**

   화면은 HTML·CSS·Canvas와 ESM JavaScript로 구성하고, esbuild가 `dist/app.js`로 묶습니다. Electron이 로컬 `dist/index.html`을 엽니다. HTTP 개발 서버, 백엔드 API, 계정, 온라인 랭킹, 멀티플레이, 클라우드 동기화는 없습니다. 게임 콘텐츠와 서체도 로컬 파일 또는 코드에 포함합니다.

   Electron 렌더러는 Node 통합을 끄고 컨텍스트 격리와 샌드박스를 사용합니다. 새 창·외부 페이지 이동을 차단하며 앱의 HTTP·HTTPS·WebSocket 요청도 차단합니다. 브라우저용 화면 빌드와 데스크톱 셸은 동일한 게임 코드를 사용합니다.

2. **화면은 라이브러리·플레이·연습·기록·아케이드·설정으로 연결됩니다.**

   음악 라이브러리는 검색, 즐겨찾기, 곡 선택, 난이도 선택, 미리 듣기와 채보 밀도 안내를 제공합니다. 플레이 화면은 고정된 네 레인과 판정선을 중심으로 그리고, 메뉴와 그래프는 플레이 영역에서 분리합니다.

   편안한 화면·선명한 화면·고대비 프리셋, 레인 폭, 노트 미리 보기 시간, 노트 밝기, 배경 밝기, 타격 효과, 타이밍·콤보 표시, 메뉴 확대를 조절할 수 있습니다. 기본 연출은 정지 배경과 작은 레인 효과입니다. 화면 회전·카메라 흔들림·전체 화면 타격 플래시는 구현하지 않았습니다.

   정밀한 색 대비 수치 검사, 광과민성 평가, 다양한 사용자의 장시간 시각 피로 테스트는 별도 검증이 남아 있습니다. 설정 옵션의 존재만으로 모든 사용자에게 시각적 편안함을 보장하지 않습니다.

3. **음원과 채보는 같은 박자 정보에서 생성합니다.**

   `src/core/content.mjs`는 오리지널 5곡과 15개 채보를 제공합니다. 각 곡은 66.5~79.3초이며 BPM과 코드 진행·선율·악기 구성이 다릅니다. 채보는 정수 마이크로초 단위의 목표 시각을 사용하고, 노트 시작과 홀드 끝은 합성 음원의 16분 박 그리드에 연결됩니다.

   `src/core/audio.mjs`는 24kHz 스테레오 PCM으로 악기 신호를 합성한 뒤 `OfflineAudioContext`로 48kHz 버퍼를 렌더링합니다. 수천 개의 오디오 노드를 한 번에 예약하는 방식 대신 버퍼를 미리 생성하며, 최근 곡·배속 3개를 메모리에 캐시합니다. 재생 중에 음악 파일을 다운로드하거나 읽지 않습니다.

   감속은 악기 음높이를 유지한 채 각 이벤트의 발생 시점을 다시 계산하여 합성합니다. 따라서 현재 내장 음악의 피치 유지 감속은 지원하지만, 임의의 외부 음원을 불러와 타임스트레치하는 기능은 없습니다.

   Windows WASAPI·ASIO를 직접 제어하는 네이티브 오디오 백엔드와 AudioWorklet 기반 전용 처리기는 현재 사용하지 않습니다. 오디오 출력은 Electron Chromium의 Web Audio를 통합니다.

4. **판정은 이벤트 시각과 오디오 기준 시간을 사용합니다.**

   오디오 출력 시각을 얻을 수 있으면 `getOutputTimestamp()`의 오디오 시각과 성능 시각을 연결합니다. 이 값에 출력 지연을 다시 빼지 않습니다. 사용할 수 없는 경우 현재 오디오 시각에서 보고된 기본·출력 지연을 한 번 반영한 추정 경로를 사용합니다.

   입력 이벤트의 원래 타임스탬프를 곡 시간으로 변환합니다. 목표 시각과의 차이를 재생 속도로 나누어 실제 시간의 오차를 얻은 뒤 입력 보정을 적용합니다.

   ```text
   실제 판정 오차 = (입력의 곡 시각 - 노트의 곡 시각) / 재생 속도 - 입력 보정값
   ```

   양수 보정은 늦게 기록된 입력을 앞당깁니다. 시각 보정은 Canvas에 그리는 노트 위치에만 영향을 줍니다. 곡 종료 뒤에도 판정용 시계는 계속 진행하며, 화면 진행률만 별도로 제한합니다.

   판정 엔진은 정수 마이크로초와 배속·허용폭의 정수 비율 비교를 사용합니다. 경계 포함 여부를 임의의 epsilon으로 바꾸지 않습니다. 표시용 소수점 반올림은 판정에 역으로 사용하지 않습니다.

   | 판정 | 절대 오차 | 점수 가중치 |
   |---|---:|---:|
   | PERFECT | 20ms 이하 | 1.00 |
   | GREAT | 20ms 초과~45ms 이하 | 0.90 |
   | GOOD | 45ms 초과~80ms 이하 | 0.60 |
   | BAD | 80ms 초과~120ms 이하 | 0.20 |
   | MISS | 유효한 입력 없음 | 0.00 |

   한 레인의 미판정 노트는 시각 순서대로 처리하고, 한 입력은 한 머리 노트에만 연결합니다. 반복 keydown은 새 입력으로 세지 않습니다. 지연 도착한 이벤트는 원래 타임스탬프로 재처리해 이미 표시한 미스·홀드 유지 결과까지 일관되게 다시 계산합니다. 원래 입력 자체가 운영체제에서 유실된 경우까지 복원하는 기능은 아닙니다.

   기본 판정창은 고정이고 연습에서는 0.25배 정밀 판정 또는 1.5배·2배 도움을 선택할 수 있습니다. 정밀 판정의 PERFECT는 ±5ms, GREAT는 ±11.25ms, GOOD은 ±20ms, BAD는 ±30ms입니다. 결과의 타이밍 탭에는 전체 시작 노트 중 보정 후 ±5ms 안에 들어온 비율도 표시합니다. +5ms 입력 보정과 ±5ms 판정창은 서로 다른 기능이며, 사용자가 모든 판정창을 임의의 ms로 각각 지정하는 편집기는 아직 없습니다.

5. **홀드는 시작 타격과 유지 완료를 따로 채점합니다.**

   홀드 시작에는 일반 타이밍 판정을 적용합니다. 보정 후 시각으로 끝보다 먼저 키를 떼면 유지 실패, 정확히 끝에서 떼거나 이후까지 유지하면 성공입니다. 중간에 놓았다 다시 눌러도 해당 홀드의 유지 실패를 되돌리지 않습니다. 시작을 놓치면 두 채점 단위가 모두 실패합니다.

   홀드 유지 성공은 1점, 실패는 0점입니다. 정확도는 전체 채점 단위의 가중치 평균, 점수는 그 비율에 1,000,000을 곱해 최종 소수점을 버린 값입니다. 콤보 배율은 없습니다. 빈 레인 입력은 점수 감점 대신 별도 횟수로 기록합니다.

   프레임별로 홀드 점수를 누적하지 않습니다. 연습 범위에 완전히 포함되지 않은 홀드는 제외합니다. 꼬리 키업의 별도 정밀 판정, 중간 복구 규칙, 연타형 롱노트는 없습니다.

6. **보정은 직접 입력과 실제 32회 탭 테스트를 지원합니다.**

   직접 입력은 ±500ms 범위에서 0.1ms 단위로 조절하며, 저장값은 정수 마이크로초입니다. 탭 테스트는 4번의 준비 박자 뒤 32회 클릭에 맞춰 Space를 누르는 방식입니다. 중앙값·MAD·표준편차·상대적 산포로 추천을 계산하며, 최소 24회 유효한 탭이 필요합니다. 추천은 사용자가 적용할 때만 저장합니다.

   이 결과에는 사람의 타격 성향이 포함됩니다. 앱이 표시하는 출력 지연 역시 장치·런타임의 추정입니다. 키 접점, USB 전달, 운영체제 스케줄링, 디스플레이 스캔아웃, 실제 공기 중 음향의 공통 시계 실측은 수행하지 않았습니다. 물리 오차 0ms 또는 특정 장비의 ±1ms 정확도를 보장하지 않습니다.

   이름을 붙인 보정 프로필을 최대 30개 저장·적용·삭제할 수 있습니다. 프로필에는 입력 보정·시각 보정·키 배치·확인된 샘플레이트가 포함됩니다. 사용자가 환경에 맞는 프로필을 직접 적용하며, 출력 장치 변경 시에는 재확인을 안내합니다. 장치 식별에 따른 자동 프로필 전환과 실측 기반 장치 인증은 구현하지 않았습니다.

7. **연습과 분석은 실제 저장된 입력에 기반합니다.**

   12개 드릴, 직접 구간 지정, 50~100% 피치 유지 감속, 메트로놈, 판정 도움, 결과에서 추천 구간으로 이동을 제공합니다. 결과 화면에서 수동으로 다시 시작하거나 미리 3·5회 자동 반복을 선택할 수 있습니다. 자동 반복은 결과 확인 시간을 2초 제공한 뒤 다음 카운트인으로 넘어갑니다. 자동 속도 상승을 켜면 정확도 95% 이상을 3회 연속 달성한 뒤 다음 반복의 속도를 5% 올립니다. 무한 자동 반복과 사용자가 목표 수치를 편집하는 기능은 아직 없습니다.

   분석은 판정 분포, 평균·중앙값 편차, 평균 절대 오차, 표준편차, MAD, 절대 오차 95백분위, 레인·패턴별 누락률, 구간별 정확도, 동시치기 시차, 홀드 실패, 불필요 입력을 제공합니다. MISS와 홀드 유지 단위는 타이밍 통계에 넣지 않습니다. 타격 표본이 없으면 0ms 대신 값 없음으로 표시합니다.

   성장 비교는 완료된 일반 플레이 중 중단되지 않고 채보·속도·판정 설정·보정·저장된 환경 조건이 같은 기록만 묶습니다. 최근 기록과 직전 대비 변화를 표시하며, 전 세계 백분위나 근거 없는 실력 점수는 만들지 않습니다.

   결과의 구간 추천과 버튼을 통해 연습으로 이동합니다. 별도의 4단계 실습 튜토리얼에서 한 키 탭·좌우 교대·동시치기·홀드를 실제로 입력해 배우며 각 단계를 반복하거나 건너뛸 수 있습니다. 튜토리얼 결과는 최고 기록에 넣지 않습니다.

   기록 화면의 5개 성취 배지는 첫 일반 완주, 일반 정확도 90%, 일반 최대 100콤보, 연습 3회 완료, 서로 다른 5곡 완주를 기준으로 계산합니다. 기록이 없으면 달성되지 않은 상태로 표시합니다. 자유롭게 그래프 범위를 드래그하는 편집, 레인별 음소거·선택 훈련, 별도 자동 시범 모드, 꾸미기 장식 해금·사용자 정의 개인 목표 관리는 아직 없습니다.

8. **다섯 아케이드는 각각 실제 입력으로 진행하는 짧은 세션입니다.**

   | 아케이드 | 현재 구현 |
   |---|---|
   | 에코 스튜디오 | 4박 듣고 다음 4박에 두 키로 재현, 여섯 라운드 |
   | 빈 박자 챌린지 | 일부 8박 구간의 소리·시각 박 안내를 숨긴 템포 유지 |
   | 비트 공방 | 두 레인의 부품 타격·홀드와 품질 결과 |
   | 리듬 가드 | 좌우 공격의 타격·홀드 방어와 성공 수 |
   | 비트 루트 | 5×5 보드에서 네 방향 명령을 기억하고 박에 맞춰 실행 |

   공통 판정 엔진과 출력 타임스탬프 변환을 사용하고, 현재 설정의 키와 보정값을 적용합니다. 각 세션은 100BPM에서 약 30초이며 본편 점수와 별도 기록합니다. 현재 단계에서는 고정 패턴을 반복 연습합니다.

   공방의 누적 생산·재화 시스템, 가드의 체력·생존 종료, 루트의 자유 경로 편집, 아케이드의 장기 진행 단계·확장 콘텐츠는 구현하지 않았습니다. 아케이드 기록은 요약 수치이며 본편과 같은 상세 리플레이를 제공하지 않습니다.

9. **저장은 로컬 JSON 데이터이며 SQLite와 서버를 사용하지 않습니다.**

   데스크톱 앱은 Electron 사용자 데이터 폴더 안 `library/`의 JSON 파일을 사용합니다. 본편·설정은 `library.json`, 이전 유효 묶음은 `library.backup.json`, 즐겨찾기·아케이드·프로필은 각각의 파일에 저장합니다. 허용된 키만 통과시키는 preload/IPC 경계를 사용하고, 각 파일은 임시 파일에 쓴 뒤 이름을 바꿔 교체합니다. 브라우저 미리보기의 대체 경로는 localStorage입니다. SQLite와 서버 데이터베이스는 사용하지 않습니다.

   본편·연습 기록에는 판정과 입력 타임스탬프, 설정, 채보 버전, 재생 속도, 환경 정보가 포함됩니다. 성취 배지는 이 기록으로 계산합니다.

   저장 데이터와 가져올 백업은 스키마·범위·중복 ID·판정 집계의 일관성을 검사합니다. 설정과 플레이 기록은 버전이 있는 하나의 데이터 묶음으로 관리하고, 마지막 유효 데이터를 복구용으로 보존합니다. CSV는 개별 판정과 단위를 포함하며 수식처럼 해석될 수 있는 문자열도 방어합니다.

   전체 JSON 백업에는 설정, 본편·연습 기록과 입력 리플레이, 즐겨찾기, 아케이드 요약 기록, 보정 프로필이 포함됩니다. 가져오기는 병합이 아닌 교체이며, 가져오기 전에 기존 백업 다운로드를 시작합니다. 각 저장 파일은 개별적으로 교체하고, 여러 파일 전체를 묶은 데이터베이스 트랜잭션은 사용하지 않습니다. 파일 쓰기·백업 저장 실패는 오류로 표시합니다. 저장 용량 무제한·모든 디스크 고장 복구·운영체제 전원 장애에 대한 절대 보장은 없습니다.

   클라우드 동기화, 계정, 서버 검증, 부정행위 방지, 온라인 순위, 자동 업데이트 서비스는 범위 밖입니다. 외부 음원·채보 가져오기와 채보 편집기도 아직 없습니다.

10. **자동 검증과 실제 환경 검증의 범위는 구분합니다.**

    `npm test`는 판정 경계·5ms 보정·배속·홀드·지연 입력 재처리·30/60/120/240FPS 상당의 이벤트 스케줄·리플레이·콘텐츠 무결성·통계·보정 추천·저장 및 백업 검증을 실행합니다. FPS 테스트는 같은 이벤트 타임스탬프에서 논리 결과가 같은지 확인하는 시뮬레이션입니다.

    실제 Chromium에서는 다섯 곡과 0.5배속 합성, 음원 파형의 유한성·음량 존재·클리핑 여부, 캐시 재사용, 재생·일시정지·재개·비동기 시작 취소를 확인했습니다. 해당 개발 환경의 합성 시간은 일반 속도 약 0.3~0.5초, 0.5배속 약 0.8초였습니다. 다른 PC의 성능 보장값으로 사용하지 않습니다.

    Electron UI 스모크 테스트에서는 음악 선택·즐겨찾기·5ms 설정 저장·드릴 목록을 확인하고, 실제 키보드 이벤트로 구간을 연주했습니다. 결과의 타이밍·패턴·구간 탭, 리플레이가 새 기록을 만들지 않는 동작, 아케이드 진입, 재로드 뒤 로컬 기록과 보정값 유지도 확인했습니다. `artifacts/smoke-results.json`에 검사 결과를, 같은 폴더에 화면 캡처를 남깁니다. 테스트 개수는 실행 결과를 기준으로 확인합니다.

    1080p 120FPS는 기획 목표이며, 다양한 PC에서의 장시간 프레임 안정성·오디오 언더런·물리 입력 지연·실제 음향과 화면의 동기화는 아직 검증이 남아 있습니다. 본편은 프레임 지연을 관찰해 기록하지만, 네이티브 드라이버 수준의 언더런과 모든 입력 유실을 측정하는 장비는 포함하지 않습니다.
