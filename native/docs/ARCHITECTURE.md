# MuWorld Windows 네이티브 구조

MuWorld의 실행 앱은 C#·.NET 10·WPF로 만든 Windows 데스크톱 프로그램이다. WPF가 메뉴·설정·분석 화면을 그리고, `DrawingContext`가 플레이 레인과 노트를 그린다. 실행에 Electron, WebView, Chromium, HTML 또는 JavaScript 런타임을 사용하지 않는다.

앱은 실행 중 100% 오프라인으로 동작한다. 음악·채보·글꼴·그림을 로컬에서 읽거나 생성하며, 서버·계정·클라우드 저장·원격 분석 수집을 사용하지 않는다. 개발 환경의 최초 .NET SDK/NAudio 패키지 복원은 배포 앱의 실행 경로와 별개다.

## 모듈과 실행 흐름

| 모듈 | 책임 |
| --- | --- |
| `Core/Models.cs` | 정수 마이크로초 타임스탬프, 설정, 채보, 판정, 기록, 보정 프로필의 공용 모델 |
| `Core/ContentLibrary.cs` | 로컬 `Assets/content.json`, 곡·채보·드릴, 가이드와 리듬 서브게임 구성 |
| `Audio/Synthesizer.cs` | 재생 전 PCM 합성, 템포 변경, 효과음·보정 큐, 순수 오디오 시각 변환 |
| `Audio/NativeAudio.cs` | NAudio 2.2.1을 통한 WASAPI 공유 모드 이벤트 출력, 장치 시계, 재생·정지·재개 |
| `Audio/RawKeyboard.cs` | 별도 Win32 메시지 스레드의 `WM_INPUT` 수신, QPC 시각 기록, 중복 down 억제 |
| `Core/RhythmEngine.cs` | 판정·홀드·점수·콤보·지연 입력 재처리. 화면이나 WPF에 의존하지 않음 |
| `Core/Analytics.cs` | 타이밍·레인·패턴·구간·홀드·동시치기 분석, 비교 그룹, CSV |
| `Core/LocalStore.cs` | 설정·기록·즐겨찾기·프로필을 포함한 단일 JSON과 원자적 저장 |
| `Views/GameSession.cs`, `Controls/GameSurface.cs` | 입력 큐 처리, 세션 수명주기, 실제 오디오 시각에 따른 표시 |

입력 스레드는 `RawKeyEvent(VirtualKey, Pressed, QpcTicks)`를 큐에 넣는다. UI는 큐를 먼저 처리하고 `RhythmEngine.Advance()`를 호출한다. 따라서 입력을 평가하는 시각은 그 프레임의 현재 시각이 아니라 원래 수신 시각이다. 화면 갱신이 늦어지면 결과 표시도 늦어질 수 있지만, 프레임 수로 노트 시간이나 판정 폭을 계산하지 않는다.

## 시계와 판정의 정확한 의미

WASAPI의 `IAudioClock.GetPosition`은 장치 위치와 상관된 QPC 시각을 제공한다. 다음 기호는 실제 `AudioClockMath.SongTimeUs()`의 단위와 대응한다.

- `P`, `Fd`: 장치 위치와 장치 시계 주파수. `Fd`를 PCM 샘플레이트라고 가정하지 않는다.
- `Qa`: 장치 위치에 대응하는 QPC 값. **100 ns 단위**다.
- `Qe`, `Fq`: 입력을 받은 `Stopwatch` 타임스탬프와 `Stopwatch.Frequency`다.
- `S`, `Fs`: 예약된 시작 스트림 프레임과 클라이언트 PCM 샘플레이트. 현재 `Fs = 48,000 Hz`다.
- `fromUs`, `r`: 원본 곡의 시작 구간과 재생 속도다. `r`은 `decimal`이다.

```text
streamSeconds = P / Fd + Qe / Fq - Qa / 10,000,000
songTimeUs    = fromUs + RoundAwayFromZero(
                  (streamSeconds - S / Fs) × r × 1,000,000)
```

출력 장치 시계를 이미 사용하므로 여기에 장치 보고 지연을 다시 빼지 않는다. 곡이 끝나도 시계는 종료 판정 여유 시간까지 진행한다. 오디오 준비 구간의 음수 시간도 보존한다. 장치 시계가 갱신되지 않으면 정상 재생으로 간주해 계속 판정하지 않고 오류를 알린다.

`T`를 노트 목표 시각, `U`를 입력 보정 마이크로초라고 할 때 최종 편차는 다음과 같다.

```text
deltaUs = (songTimeUs - T) / r - U
```

음수는 FAST, 양수는 LATE다. `U = +5,000`은 관측된 편차에서 정확히 5 ms를 한 번 뺀다. 원시 편차가 +7 ms이면 보정 후 +2 ms이며, 설정을 7 ms로 바꾼 것이 아니다. `VisualOffsetUs`는 노트 표시만 바꾸고 이 식에는 들어가지 않는다.

실제 등급 비교는 나눗셈의 반올림을 피하도록 아래 식으로 수행한다. 숨겨진 허용 오차나 FPS별 보너스는 없다.

```text
abs((songTimeUs - T) - U × r) <= windowUs × WindowScale × r
```

| 등급 | 기본 허용 범위 | 점수 가중치 |
| --- | --- | --- |
| PERFECT | ±20,000 µs | 1.00 |
| GREAT | ±45,000 µs | 0.90 |
| GOOD | ±80,000 µs | 0.60 |
| BAD | ±120,000 µs | 0.20 |
| MISS | 유효 입력 없음 | 0 |

각 경계는 포함한다. 연습 `WindowScale = 0.25`이면 PERFECT가 정확히 ±5 ms이고, 다른 등급의 폭도 같은 비율로 줄어든다. 속도를 바꿔도 허용 범위는 실제 시간 단위다. 입력 보정, 판정 허용 폭, 시각 보정은 서로 다른 설정이다.

## 판정·일시정지·리플레이

- 레인마다 시간상 가장 앞선 미판정 노트를 대상으로 삼는다. 한 down은 한 머리만 소비하며 반복 down은 다음 노트를 치지 않는다.
- 홀드는 시작 타격과 유지 완료가 각각 하나의 채점 단위다. 보정된 끝보다 1 µs라도 먼저 놓으면 유지 실패이며, 다시 눌러도 복구되지 않는다. 끝에 맞춰 놓거나 더 오래 누르는 것은 성공이다. 머리를 놓치면 유지도 실패다.
- 연습 구간은 머리가 `[fromUs, toUs)` 안에 있고 홀드 끝도 `toUs` 이내인 노트만 포함한다. 경계를 가로지르는 홀드를 임의로 잘라 만들지 않는다.
- 과거 타임스탬프를 가진 입력이 늦게 도착하면 입력 로그를 시간순으로 다시 처리한다. 이미 표시된 MISS나 임시 홀드 성공이 수정될 수 있다. 저장과 분석에는 `Snapshot()`/`Finish()`의 현재 결과를 사용한다.
- 일시정지 직전 대기 입력을 먼저 처리한다. 현재 라이브 플레이는 눌린 레인을 해제하여 기록하며, 일시정지를 포함한 기록에는 `Interrupted`를 남긴다. 리플레이를 멈출 때는 원본 로그에 가상 해제를 추가하지 않는다.
- 재개 준비 동안에는 새 플레이 입력을 평가하지 않는다. 원래 곡 위치에 도달한 뒤 수집을 재개한다. 곡이 이미 끝난 판정 여유 구간도 다시 음악을 재생하지 않고 시계를 이어간다.
- `Finish()` 이후 입력은 받지 않는다. 최종 확정 전에 입력 큐를 처리하고, 설정된 최대 판정 폭과 보정에 맞는 종료 여유 시간을 확보해야 한다.

정확도는 판정 완료 단위의 가중 평균이고, 점수는 전체 채점 단위를 기준으로 1,000,000점에 환산한다. 플레이 중 정확도가 높아도 아직 남은 노트까지 성공했다는 의미는 아니다.

## 분석과 로컬 데이터

타이밍 평균·중앙값·평균 절대 오차·모표준편차·MAD·절대 오차 p95는 성공한 머리 타격의 보정 후 실제 시간 편차로 계산한다. MISS와 홀드 유지 단위는 0 ms 표본으로 섞지 않는다. 표본이 없으면 통계는 `null`이며 화면에는 미측정으로 표시한다. 동시치기 간격은 모든 레인의 타격이 확인된 묶음만 측정한다.

성장 비교는 완료한 일반 플레이 중 중단이 없는 기록을 대상으로 한다. 채보와 버전·난이도·속도·입력 보정·판정 폭·키 배치·저장된 환경 정보가 같은 기록끼리 묶는다. 이 비교는 저장된 환경 정보의 일치 여부이며, 모든 물리 장치나 펌웨어 변경을 실측해 식별한다는 의미는 아니다.

일반 데이터 디렉터리는 다음과 같다.

```text
%LOCALAPPDATA%\MuWorldNative\
  library.json         설정·기록·즐겨찾기·보정 프로필
  library.backup.json  직전의 유효한 전체 데이터
  error.log            처리하지 못한 UI 예외의 로컬 진단 기록
```

`LocalStore(directory)`로 테스트용 위치를 지정할 수 있다. 앱의 `--smoke`/`--capture` 모드는 `%TEMP%\MuWorldNative-QA`를 사용한다. 데이터와 진단 기록은 자동 업로드하지 않는다.

저장은 같은 디렉터리의 임시 파일에 기록하고 flush한 뒤 교체한다. 기존 기본 파일이 유효하면 직전 파일을 백업으로 보존한다. 읽기 실패 시 유효한 백업으로 복구하고 이를 알린다. 가져오기는 스키마·버전·필수 필드·설정 범위·기록 집계·중복 ID·프로필을 모두 검증한 뒤 전체 데이터를 반영한다. 정수 마이크로초와 `decimal` 속도/배율을 유지한다. 현재 한도는 기록 500개, 프로필 30개, 전체 JSON 60 MB다.

## 검증 범위와 알려진 한계

저장 단위가 1 µs이고 판정 산술이 정확하다는 것은 **물리 입력 오차 0 ms**라는 뜻이 아니다. Raw Input 시각은 전용 메시지 스레드에서 받은 순간이며, 키 접점이 닫힌 순간을 직접 측정하지 않는다. 키보드 스캔·디바운스·전송·OS 스케줄링·오디오 드라이버·DAC·화면 스캔아웃의 지연과 변동은 남는다. 48 kHz 오디오는 한 샘플이 약 20.83 µs다. 보고된 오디오 지연과 요청한 10 ms 버퍼도 물리 왕복 지연의 보장값이 아니다.

32박 탭 보정은 사용자의 타격 습관이 포함된 체감 보정이다. 장치 지연을 분리해 실측하려면 전기적 입력 신호·오디오 출력·화면을 공통 외부 시계로 측정해야 한다. 소프트웨어 테스트나 정밀 모드의 성공 결과만으로 그 검증을 대신하지 않는다.

현재 독립 콘솔 테스트는 36개이며 외부 테스트 프레임워크가 필요 없다. 저장소 루트의 PowerShell에서 실행한다.

```powershell
& .\.tools\dotnet\dotnet.exe run --project .\native\MuWorld.Native.Tests\MuWorld.Native.Tests.csproj --configuration Release
```

검증 항목은 모든 판정 경계, decimal 배속, ±5 ms 정밀 모드, 음수 보정의 마감 시각, 홀드 해제 경계, 지연 입력 재처리, 30/60/120/240 FPS와 프레임 정지의 동일 리플레이, 통계의 MISS 제외, 저장·가져오기 원자성, 파일 잠금 실패와 백업 복구다. 오디오 순수 함수 테스트는 서로 다른 장치 주파수와 QPC 단위, 과거 이벤트, 시계 앵커 연속성을 검증한다. PCM 테스트는 결정성·템포별 길이·취소를 확인하며, 스펙트럼 투영으로 0.8배속에서도 기준 저음 220 Hz가 유지되는지 검사한다.

이 테스트들은 계산·상태·파일 동작의 검증이다. 실제 WASAPI 장치와 Raw Input 입력 전달, DPI·전체 화면·창 전환·렌더링은 네이티브 실행 QA로 따로 확인해야 한다. 기존 JavaScript/Electron 실험 코드의 테스트 결과를 네이티브 앱 검증 결과로 대신 사용하지 않는다.
